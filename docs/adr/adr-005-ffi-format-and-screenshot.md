# ADR 005: FFIの保存形式の指定とスクリーンショット関数

## Status

Accepted

## Context

ADR-003で、録音のFFIをC ABIと整数IDのハンドルで公開すると決めた。停止関数はファイルパスを受け取り、Rust側でWAVに書く設計だった。

その後、ADR-004でMP3エンコードを追加した。CLIはMP3で保存するようになった。FFIの呼び出し側もMP3を選べる必要がある。

また、Javaから呼ぶ用途では、録音だけでなくセッション開始時のスクリーンショットも必要である。ADR-003はスクリーンショットのFFIを別ADRに先送りしていた。

FFIの関数シグネチャは、後から変えると呼び出し側のコードも書き直しになる。このため、実装前に決める。

## Decision

### 保存形式は整数の形式コードで指定する

`sss_stop_recording`に`format: i32`の引数を足す。`0`がWAV、`1`がMP3である。不正なコードは`SSS_ERR_INVALID_FORMAT`を返す。

```rust
pub extern "C" fn sss_stop_recording(id: u64, format: i32, path: *const c_char) -> i32;
```

### スクリーンショットはハンドルなしの1関数で公開する

```rust
pub extern "C" fn sss_capture_primary_monitor(path: *const c_char) -> i32;
```

撮影と保存を1回の呼び出しで行う。状態を持たないので、IDもレジストリも要らない。画像データは境界を越えず、PNGファイルとして書く。

### 引数の検査は録音を取り出す前に行う

形式コードとパスが不正なら、レジストリから録音を取り出す前にエラーコードを返す。録音は止まらず、呼び出し側は引数を直して再度停止できる。誤った引数で録音データを失わないためである。

### エラーコード

| コード | 定数 | 意味 |
| --- | --- | --- |
| 0 | `SSS_OK` | 成功 |
| 1 | `SSS_ERR_INVALID_ID` | IDが無効（未知、または停止済み） |
| 2 | `SSS_ERR_INVALID_PATH` | パスがNULL、またはUTF-8でない |
| 3 | `SSS_ERR_INVALID_FORMAT` | 形式コードが不正 |
| 4 | `SSS_ERR_SAVE_FAILED` | ファイルの保存に失敗 |
| 5 | `SSS_ERR_CAPTURE_FAILED` | スクリーンショットの取得に失敗 |
| 99 | `SSS_ERR_PANIC` | Rust側のpanicを境界で止めた |

## Alternatives

### Alternative 1: パスの拡張子で形式を決める

`.mp3`ならMP3、それ以外はWAVとする。引数が増えない。

しかし、呼び出し側が拡張子を間違えると、意図と違う形式で黙って保存される。形式の指定と保存先の名前は別の関心事である。採用しなかった。

### Alternative 2: 形式ごとに停止関数を分ける

`sss_stop_recording_wav`と`sss_stop_recording_mp3`の2関数にする。引数の検査が要らない。

しかし、形式が増えるたびに関数が増える。Java側でも形式ごとにMethodHandleを作ることになる。形式コードなら1関数で済み、呼び出し側は定数を切り替えるだけである。採用しなかった。

### Alternative 3: スクリーンショットのピクセルを境界越しに返す

幅、高さ、RGBAのバッファへのポインタを返し、呼び出し側が解放関数を呼ぶ。呼び出し側で画像を加工できる。

しかし、ADR-003で録音データをファイル経由にしたのと同じ理由で、解放の責任が境界の両側にまたがる。今の要件はPNGとして保存することだけである。採用しなかった。

## Confidence Level

高い。

形式コードによる指定は、C言語のライブラリで一般的な形である。スクリーンショットの関数は状態を持たないので、設計上の不確実さがない。

次の状況になったら見直す。

- 呼び出し側でスクリーンショットを加工する要件が出たとき。Alternative 3の設計が必要になる。
- 指定ウィンドウのスクリーンショットをFFIで公開するとき。ウィンドウの指定方法（タイトル、ハンドル）を決める必要がある。
- エラーの詳細（どのデバイスで何が失敗したか）が呼び出し側に必要になったとき。最後のエラーメッセージを取得する関数を追加する。

## Consequences

### 良い影響

- 呼び出し側がWAVとMP3を1つの関数で選べる。
- スクリーンショットと録音の両方をJavaから呼べ、CLIと同じセッションを別言語で組み立てられる。
- 不正な引数で録音データを失わない。

### 悪い影響

- `sss_stop_recording`の引数が1つ増える。ADR-003のシグネチャとは互換性がない。ただし、ADR-003の時点では実装がなかったので、書き直す呼び出し側のコードはない。
- 形式コードの意味（0がWAV、1がMP3）を呼び出し側が知っている必要がある。READMEに表を置く。

### 中立な影響

- FFIのテストはRustから`extern "C"`関数を直接呼ぶ。C ABI越しの呼び出しはテストしていない。Java側の動作確認は手動である。
- 録音を使うテストは音声デバイスを取り合うので、lib.rsのテストと同じロック（`AUDIO_DEVICE`）で直列化する。
